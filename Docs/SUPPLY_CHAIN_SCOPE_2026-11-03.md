# Supply Chain Puzzle — scope before code
SC-RCH-009. Original turn-based factory planning: deliver four modules within twenty shifts. Start two ore; caps ore8/plates6/modules4. Extract +3 ore; smelt consumes2 ore produces1 plate; assemble consumes2 plates produces1 delivered module. Each order costs one shift. Overflow/insufficient inputs rejected, not silently wasted. Delivery4 wins, shift20 without target loses; explicit abandon ends failed contract. Exact recipes/output/storage and remaining shifts visible before orders. A legal seventeen-shift solution exists. No real market, colony, inventory, money or NPC changes.

Starcade owns fictional factory and plain schema1 action history, max20 orders. Existing host save/finish only; every order checkpoints. Native save preferred; local standalone fallback. Restore replays legal actions; completed restore never repeats reward. Bad save -> visible fresh contract. New contract requires confirmation if unfinished. Return/death/travel/unload/quest stop preserve last shift, no timers or world cleanup. Crash between result save and notification may omit reward; exactly-once receipts not claimed.

Horizontal entries: catalog/iframe load, keyboard/D-pad/mouse, affordability/capacity on UI and engine, result/native score, save/reload/new/abandon. All route to one action owner. No sibling adapters: OC owns actual colony production, SSSE real markets, IS vessels, CT staff; fictional delivered modules have no economic meaning outside Starcade. No background work or global lock.

Acceptance before code: legal win, timeout, abandon; recipe conservation, capacity and insufficient-resource rejection; every-shift restore; invalid/oversize/action-after-result rejection; browser full contract/reload/one finish/finished reload and controller-style navigation. Actual Starfield readability/input/performance/fun remain separate gates.
