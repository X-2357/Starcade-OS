# Race Director — full lifecycle before code
SC-RCH-006: fictional eight-lap race strategy. Forecast dry/wet lap before order; select conserve (70 seconds, 1 fuel, 1 wear), normal (66/2/2), push (60/3/4), or pit lap (84 seconds, gain 10 fuel capped18, reset wear). Wet adds six seconds/two wear to push. At wear12 a puncture adds18 seconds and leaves wear4. Costs and consequences preview before selection. Start fuel12/wear0; five seeded fictional rivals have fixed total times. Finish eight laps -> rank; explicit retirement -> DNF. Fuel-starved orders disabled in UI and rejected in engine; pit always available so no softlock.

Race Director owns only fictional run resources/time/results. No wagers, world ships, real personnel/league careers, credits, markets, new native/CK/Papyrus or sibling adapter. IS owns real racing/vessels, CT real staff, SSSE economy. Existing host save/finish path; no timers or background polling. Other games unchanged.

Lifecycle active -> completed/retired; schema1 seed/history, max8 orders, legal replay restore. Every order checkpointed; reload result never repeats finish. Explicit new race requires confirmation when unfinished. Return, death, travel, quest stop and unload retain last order; no mutable world state to restore. Bad/unsupported save gives visible fresh run. Crash between result save and finish can omit notification; no exactly-once reward claim. No copied assets.

Horizontal entries: catalog/iframe ready-load, keyboard/D-pad/mouse orders, pit/fuel affordability, native score/result, save/reload/new/retire. Same engine action owner feeds all. Diagonal acceptance full race -> reload -> no repeated finish; unaffordable order -> rejected; puncture/pit forecast -> actual log; midrace save -> resume; keyboard -> action; retire -> terminal. Seeded race completeness, bounds, replay equivalence and browser lifecycle required; actual Starfield/performance/fun separate.
